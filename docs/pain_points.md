# 工具轉角 — 後端解決了題目哪些痛點

社區資源共享平台 · 後端功能對應說明（給簡報 / Q\&A 用）

> 主軸：讓社區居民把閒置物品拿出來共享，鄰居可借用、歸還， 降低重複購買與資源浪費。以下把「題目痛點 → 後端怎麼解 → 對應 API」對齊。

---

## 一、痛點對應表

| \# | 題目痛點 | 後端解法 | 對應 API |
| :---- | :---- | :---- | :---- |
| 1 | 家中工具/物品買了很少用，閒置浪費 | 物品上架分享機制，讓閒置物流動起來 | `POST /rents` |
| 2 | 想借東西卻不知道社區裡誰有 | 公開可借清單 \+ 單品明細，人人可瀏覽 | `GET /rents`、`GET /rents/{id}` |
| 3 | 借出後不知道東西被誰借走、何時還 | 借用紀錄同時記出借人、借用人、預計歸還日 | `POST /borrows` |
| 4 | 同一件東西被重複借走、借還狀態混亂 | 借出即翻 `rent_enable=0`，清單不再顯示；歸還翻回 | `POST /borrows`、`return` |
| 5 | 有人借了不還、逾期沒人追 | 逾期查詢（借用中且過期的紀錄） | `GET /borrows/overdue` |
| 6 | 缺乏共享成效的數據佐證（SDG） | 借用統計 \+ 分類統計，量化共享成效 | `GET /borrows/stats`、`GET /stats/category` |
| 7 | 借還常有糾紛（東西壞了誰的責任） | 借用/歸還雙向拍照存證 | `/files` \+ borrow/return 照片欄位 |
| 8 | 冒名借用、資料被亂改的安全疑慮 | JWT 登入 \+ BCrypt 加密，借用人由 token 認定 | `POST /login`、Bearer token |

---

## 二、逐項說明

### 1\. 閒置物品流動（痛點 1）

居民登入後用 `POST /rents` 上架物品（分類、品項、備註、照片）， 物主自動綁定為登入者。閒置的鍋、帳篷、電鑽因此能被鄰居看見、借用， 不必人人各買一份 —— 直接呼應「共享、減少重複購買」的核心訴求。

### 2\. 資訊透明：找得到、看得懂（痛點 2）

`GET /rents` 提供公開可借清單（不需登入即可瀏覽，降低使用門檻）， `GET /rents/{id}` 看單品明細（含分類、照片、物主）。 解決「想借卻不知道社區有什麼」的資訊不對稱。

### 3\. 借還全程可追蹤（痛點 3、4）

`POST /borrows` 建立一筆借用紀錄，**同時記錄出借人、借用人、預計歸還日**， 並用原子性的旗標把物品狀態切成「已借出」，避免同一件被重複借走。 `PATCH /borrows/{rentId}/return` 歸還後物品自動重新上架。 借還狀態不再靠口頭或紙本，系統即時反映。

### 4\. 逾期治理（痛點 5）

`GET /borrows/overdue` 撈出「仍在借用中且已過預計歸還日」的紀錄， 讓管理者掌握誰逾期，作為後續提醒/催還的依據。

### 5\. 成效數據化，扣合 SDG（痛點 6）

`GET /borrows/stats` 給出累積借用、借用中、已歸還、逾期的筆數； `GET /stats/category` 用資料庫 view 統計各分類物品數，可直接畫長條圖。 這些數據讓「共享減少浪費」不只是口號，而有量化佐證 （對應 SDG 12 負責任的消費與生產）。

### 6\. 借還存證，降低糾紛（痛點 7）

三個拍照時機：上架介紹照、借用人借用時拍照、出借人歸還時拍照。 透過 `POST /files` 上傳取得圖片 url，分別存進物品與借用紀錄。 東西借出前後的狀態有影像紀錄，減少「誰弄壞的」爭議。

### 7\. 身分安全（痛點 8）

`POST /login` 以 BCrypt 驗證密碼、發放 JWT（HS512）， 之後請求帶 `Authorization: Bearer <token>`。 **借用人身分由 token 認定，前端無法冒名**，確保借用紀錄的可信度。

---

## 三、誠實揭露（已知限制，供 Q\&A 先準備）

- **擁有權檢查未做**：目前編輯/刪除/上下架/歸還只驗「有沒有登入」， 未驗「是不是你的物品/你的借用」。demo 可用，正式版需補權限。  
- **逾期為全站視角**：`/borrows/overdue` 回全部人的逾期，非「我的」。  
- **逾期僅查詢、無主動提醒**：尚未做推播/通知。  
- **技能教學模組未實作**：本次刻意聚焦物品借用主線，取捨換取完整可跑的功能。  
- **高併發搶借**：改用 `save` 後失去單句條件式 update 的原子性， 極端併發下有微小競態窗；正式版可加 `@Version` 樂觀鎖。

>   
> 這些「沒做」是有意識的取捨，把時間投在能完整跑通的核心借還流程上， 是可以在 Q\&A 大方說明的加分點（展現對系統邊界的判斷力）。
